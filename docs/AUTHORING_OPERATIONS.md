# Authoring Operations

CUT projects, asset exports and YCD builders accept an optional
`AuthoringOperation` for progress and cooperative cancellation. One token can
cover construction, validation and saving without changing asset encoding.

```python
from fivefury import (
    AuthoringOperation,
    AuthoringProgress,
    YcdCutsceneBuilder,
)

def receive_progress(progress: AuthoringProgress) -> None:
    print(progress.stage, progress.asset, progress.completed, progress.total)

operation = AuthoringOperation(progress=receive_progress)
builder = YcdCutsceneBuilder.create("scene", duration=5.0)
builder.prop("actor")
assets = builder.build_ycds(operation=operation)
```

`build_section`, `build_ycds`, `validate` and `save` accept `operation=`.
The operation is optional and does not change precision policy or generated bytes.

## Threading And Cancellation

- Callbacks execute synchronously on the authoring thread. Dispatch to your UI's
  event queue rather than updating UI objects directly from the callback.
- Another thread can call `operation.cancel()`. The next checkpoint raises
  `AuthoringCancelled`; a cancelled operation cannot be reused.
- Validation checks cancellation between sequence blocks. Encoding and resource
  serialization complete their current unit of work before reaching a checkpoint.
- Saving validates every section before writing final files. Each replacement is
  atomic. `CutsceneAssets.save` stages the complete batch before replacing files:
  cancellation during preparation leaves existing outputs intact. Replacement is
  non-cancellable; ordinary replacement failures roll back completed replacements.
  This is not a filesystem-wide power-loss transaction. Direct YCD builder saves
  still replace sections individually.
- Callbacks and cancellation never bypass validation or change tolerances.

## Progress Units

`AuthoringProgress` contains a typed `AuthoringStage`, an asset name, a completed
count and a total count. Counts belong to that stage and asset, not a global
percentage: building reports sections, validation reports constrained tracks in
one YCD, and writing reports output files.

## Precision And Mutation

Validation reads the serialized resource back before comparing samples. Native
comparison interpolates stored channels before reconstructing or normalizing
cached quaternions. Integer errors and fractional angular errors retain separate
diagnostics; fractional checks include sequence overlaps.

Build reuse is scoped to one call. Editing tracks and building again constructs
and validates new assets. No precision result or serialized output is cached on
the mutable builder for later calls.

## CUT Projects And Facial Tracks

```python
from fivefury import (
    AuthoringOperation, CutsceneProject, Quaternion, Vector3, YcdFacialTrackSet,
)

project = CutsceneProject.create("dialogue", duration=2.0, camera_cuts=[1.0])
actor = project.scene.ped("speaker", model_name="cs_actor")
project.camera(position=Vector3(0, -3, 1), rotation=Quaternion())
project.animate(
    actor,
    clip="speaker",
    mover_position=Vector3(),
    facial=YcdFacialTrackSet(controls={7: {0.0: 0.0, 1.0: 0.8, 2.0: 0.0}}),
)

operation = AuthoringOperation(progress=receive_progress)
assets = project.build(operation=operation)
assets.validate(operation=operation).raise_for_errors()
paths = assets.save("output", operation=operation)
```

`facial=` accepts `YcdFacialTrackSet` on ped bindings only. Omit the body arguments
for a facial-only clip. The project derives the merged facial state and writes
`speaker_dual-0`, `speaker_dual-1`, etc.; the CUT streaming base remains `speaker`.
Omitting `facial=` preserves body-only authoring. Control IDs and values must
match the ped's expression assets; the sample ID above is not universal.

Pass `context=BuildContext(...)` to `assets.validate`, `build_files` or `save`
to check model, skeleton and expression dependencies from loose assets or a game
cache. These validations are not proof of playback in the game.

`CutsceneProject.build`, `CutsceneAssets.build`, `validate`, `build_files` and
`save` accept `operation=`. The same token reaches YCD construction, precision
validation and serialization. Checkpoints occur between sections, clips, tracks,
validation phases and output preparations. Compression, an individual asset
read and other current units finish before cancellation is observed.

Progress counts are local to each unit of work and can restart on a later pass;
they are not a monotonically increasing percentage for the whole project.
